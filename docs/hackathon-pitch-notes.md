# HOW I VIBE-CODED CLOUDREADY

### From learning need to working product

**PROMPT → IMPLEMENT → TEST → REFINE → DEPLOY**

**01 — PROMPT**
Defined specific features, constraints and expected behaviour for an AZ-900 practice quiz.

**02 — IMPLEMENT**
Used AI-assisted coding to develop the quiz, scoring, domain-level performance tracking and dashboard.

**03 — TEST**
Checked quiz behaviour, score calculations, existing features and regression outcomes instead of assuming generated code was correct.

**04 — REFINE**
Used test results and identified limitations to guide the next development steps, while managing changes through Git.

**05 — DEPLOY**
Published the application using GitHub Pages and documented the project with a README and screenshots.

### My approach

_AI accelerated development; testing and judgement guided the decisions._

**Evidence:** GitHub repository · Working live demo · Regression checks · Project documentation

### Note

I approached CloudReady as an iterative AI-assisted development project, not a one-shot code-generation exercise. I used specific prompts to guide implementation, broke the work into manageable features, and tested the results as the application evolved. When a limitation was identified, I kept it visible rather than claiming the feature already existed. I then used Git to manage changes and GitHub Pages to publish the working application. For me, the value of vibe coding is not simply how quickly AI produces code, but how effectively we direct, verify and refine that code to solve a real learning problem.
